Because no code is the best code.

Rig is a shared vocabulary for creative work — not character rigging. Tools, packs, and AI agents pass scenes, sequences, graphs, and signals between each other. There is no library to link, no runtime to embed, and no API to version. It ships as agreement.

Every creative tool speaks only to itself

Creative software is full of excellent editors that cannot exchange a single object. A patch, a scene, a sequence, a light rig — each lives in a private file format that only its author's program understands.

The format problem

Node editors, sequencers, and visual tools each invent their own project file. Moving work between two of them means writing a converter, and converters rot.

The library problem

Shared runtimes solve interop by making everyone depend on the same code — which locks the language, the version, and the platform, and rules out the small embedded host entirely.

The AI problem

A model can write a renderer in an afternoon. It cannot invent a vocabulary that the next session, the next model, and someone else's app will all agree on.

Rig is not another editor. It is the vocabulary editors could share.

Concept is more important than execution

What a transform is — position, rotation as a quaternion in x, y, z, w order, scale — outlives every renderer that ever drew one. Renderers get rewritten: new language, new GPU, new decade. The concept does not decay, and neither does any document written against it.

So Rig keeps the concept and leaves the execution to you. The specification contains schemas, units, and rules — the parts that are expensive to agree on and cheap to keep. It contains no renderer, because renderers are the easy, disposable part.

Contract — the concept

Two loop rules, schema ids, field names, units, datatypes. Portable, versioned, written down, never compiled.

Fulfillment — the execution

Any code that honors the Contract: a host, a pack, a renderer, a UI. Yours to write, yours to replace.

What travels

Hosts run a four-hook loop. Content is plain data composed onto entities, keyed by schema id. That is the whole model. 

Setup  → spawn / load entities
Update → simulate (modulators, transport, …)
Draw   → present
Exit   → tear down

One entity, in full — and the picture below is that document drawn by a second fulfillment (static SVG, zero client JavaScript):

Built for AI and human developers

When execution gets cheap, agreement becomes the scarce asset. A generated renderer is fine and disposable. A generated vocabulary is a liability, because the next session invents a different one.

So the specification is published in a form people and models read the same way: prose for meaning, JSON Schema for enforcement, golden examples to copy instead of invent, and a validator that closes the loop. 

node tools/rig-validate/cli.js path/to/doc.json

Every failure names a JSON Pointer, so an agent can correct itself without a human interpreting the error. Two agents working in two unrelated applications converge on compatible data — not because they coordinated, but because they read the same catalog.

How it relates to what exists

Rig overlaps with several good things without replacing any of them.

Prior artScopeHow Rig differs
Node editors — TouchDesigner, Max, vvvv, Cables Complete applications. They are code (Python, GLSL, expressions, node ABIs) under a GUI, with private project formats. Rig is not an application. It is the shared vocabulary those editors would need to exchange work.
glTF 3D delivery, spec-first, no required library Same instinct, wider domain: 2D and 3D, music and transport, pixels, node graphs, LEDs, sensors.
OpenUSD 3D scene interchange with a large reference implementation Schema-first like USD, but nothing to link. USD's own guidance warns against plugins depending on a shared library.
OSC, MIDI Live message transport Complementary. Those move events between running programs; Rig names the things events act on.

What Rig is not

Not an editor

There is no Rig application to download. Editors are fulfillment, and there can be many.

Not a library

Nothing to install, link, or upgrade. Adopting Rig is a decision, not a dependency.

Not "you will never program"

Someone writes the host. The framework ships no code; your app still does.

Not finished

0.x is a draft. Core rules hold; schemas may grow or tighten before 1.0.0.

Start

Clone it, check it, read it. There is nothing to install but the validator.

git clone https://github.com/rigkid/RigWorks
cd rigworks
npm run setup    # installs the validator
npm run check    # schemas, parity, links, golden documents

Being Rig takes two rules: a four-hook loop and plain-data components. Everything else is opt-in.

Reference host: RigKit — desktop fulfillment on GLFW and OpenGL.
